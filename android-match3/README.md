# 宝石三消 · Android

主流玩法的手游三消：**8×8 棋盘、6 种宝石、限步数冲目标分、三档星级**，
带 4 连直线消、5 连彩虹球、L/T 形爆炸这三种道具。

和 [2048](../android-2048/) 一样，**不依赖 Gradle / AGP / AndroidX / 任何第三方库**——
界面、动画、图标全部自己画，构建走 `javac + aapt2 + d8 + apksigner` 的手工链路。
APK 只有 **45 KB**，**不申请任何权限**。

## 安装

仓库里带了编译好的 `match3.apk`（调试签名，个人装没问题）：

1. 把 `match3.apk` 传到手机（微信/数据线/网盘都行）
2. 手机上点开它，按提示允许"安装未知来源应用"
3. 或者用数据线：

```powershell
D:\android-sdk\platform-tools\adb.exe install -r .\match3.apk
```

支持 Android 5.0（API 21）及以上。

## 玩法

- **拖动/点击相邻两格交换**，凑成 3 个及以上同色即消除；只能交换**能凑成三连**的两格，
  换错了会自动弹回原位
- 每关有**步数上限**和**目标分**，步数用完还没达标就失败，可以重玩
- 达标得 1 星，**1.5 倍**目标分 2 星，**2 倍**目标分 3 星（星级存本地，逐关累积）
- 卡住 4 秒会**自动提示**一个可行走法（黄色描边）；真的无路可走时自动打乱重排

**三种道具**（主流三消的通用规则）

| 形状 | 道具 | 效果 |
|---|---|---|
| 横向/纵向 4 连 | 直线宝石 | 消掉整行或整列 |
| L 形 / T 形（横竖交叉） | 爆炸宝石 | 炸掉周围 3×3 |
| 直线 5 连 | 彩虹球 | 消掉棋盘上**全部同色**宝石 |

- 道具由**本次交换的那一格**优先生成（符合主流手感：你想在哪儿要道具就在哪儿换）
- 道具**用一次就没了**：单独消掉它会触发效果；彩虹球和任意宝石交换即刻触发

**计分**

```
得分 = 消除格数 × 20 × 连锁层数  +  生成道具数 × 60 × 连锁层数
```

连锁层数是**同一次下落里第几波**消除：第一波 ×1，第二波 ×2，第三波 ×3……
所以真正的高分来自"一步引发连环塌陷"，而不是单次消得多。这是三消玩法的核心爽点，
测试里专门跑长局统计过（见下）。

**关卡曲线**

| 关卡 | 目标分 | 步数 |
|---|---|---|
| 1 | 1500 | 24 |
| 4 | 4200 | 23 |
| 10 | 9600 | 21 |
| 22 | 20400 | 18（下限） |

公式是 `目标 = 1500 + (关-1) × 900`、`步数 = max(18, 24 - (关-1)/3)`。

## 界面

全部 Canvas 手绘（没有布局 XML、没有图片资源，图标是脚本生成的 PNG）：

- 深色背景 + 6 种宝石各有**渐变配色 + 不同的内部图形**（不靠颜色也能区分，色盲友好）
- 直线宝石画条纹、爆炸宝石画放射线、彩虹球画六色环——一眼能认出来
- **四段式动画状态机**：交换 150ms → （换错则）弹回 → 消除 220ms → 下落 190ms，
  下落用真实重力加速而不是匀速，落地有轻微压扁
- 顶部 HUD：关卡、分数、**目标进度条**、剩余步数，还有"提示"和"重玩"两个圆角按钮
- 过关/失败弹全屏半透明结算层，过关时三星逐颗弹出
- 屏幕常亮、锁定竖屏

## 构建

```powershell
# 1) 一次性准备工具链（下载 Android SDK 的 cmdline-tools + platform + build-tools）
powershell -ExecutionPolicy Bypass -File ..\.build\setup_android_sdk.ps1

# 2) 编译 + 跑自测 + 出 APK
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

需要：JDK（用 `javac`/`keytool`/`jar`）+ Android SDK 的 `platforms;android-34` 与
`build-tools;36.1.0`。**不需要 Gradle、不需要 AGP、不需要联网解析 Maven 依赖**。

构建流程（每一步都在 `build.ps1` 里，带错误检查）：

```
自测       javac + java 跑 BoardTest           → 逻辑层的 219075 项断言
资源       aapt2 compile res                   → build\res.zip
清单/资源  aapt2 link -I android.jar           → R.java + 未签名 APK
源码       javac -source 8 -bootclasspath ...  → .class
转 dex     jar + d8                            → classes.dex
打包       把 classes.dex 塞进 APK + zipalign
签名       keytool 生成调试密钥 + apksigner（v1/v2/v3 三套签名）
```

> ⚠️ **同样的坑**：`build-tools;34.0.0` 自带的 d8（R8 8.2.2）遇到 **enum 类**会内部崩溃
> （`java.lang.NullPointerException: Cannot invoke "String.length()"`），
> 换 `build-tools;36.1.0` 就好了。脚本里默认用 36.1.0。

## 代码结构

```
src/com/dsh/match3/
  Board.java        三消核心逻辑 675 行 —— 不引用任何 Android API，可直接用 java 跑测试
  BoardTest.java    单元测试 446 行（纯 Java，不需要 JUnit）
  GameView.java     棋盘视图 732 行：Canvas 绘制 + 手势 + 动画状态机
  MainActivity.java 唯一的 Activity 102 行：生命周期、关卡与星级的持久化
AndroidManifest.xml 清单（minSdk 21 / targetSdk 34，未申请任何权限）
res/values/strings.xml
res/mipmap-*/ic_launcher.png   5 个密度的图标（由脚本生成）
build.ps1           手工构建脚本
```

`Board.java` 完全不碰 Android：棋盘、匹配、道具、连锁、死局检测全在里面，
所以规则改动可以在任何装了 JDK 的机器上**一秒跑完全部测试**，不用开模拟器。

## 自测

`build.ps1` 会先跑自测，不通过就中止打包。共 10 组用例、**219075 项断言**：

| 用例 | 校验内容 |
|---|---|
| 铺盘 | 60 个种子开局：**没有任何现成三连**、至少有一步可行走法、宝石种类合法 |
| 匹配检测 | 横向/纵向 3~5 连、L/T 交叉、边界不越界、不误报 |
| 交换合法性 | 只有能凑成三连的相邻交换才允许；不相邻/斜向/无效果的一律拒绝；彩虹球例外 |
| 计分与连锁倍数 | 逐项核对 `格数×20×层数 + 道具×60×层数`，连锁层数递增与清零 |
| 道具生成规则 | 4 连→直线（横竖对应）、5 连→彩虹、L/T→爆炸、优先落在交换点、一格不生成两个 |
| 道具触发效果 | 直线消整行/整列、爆炸 3×3、彩虹消全色；触发后道具本身也被清掉 |
| 下落与补充 | 每列宝石垂直压实、无悬空、空格补满、**颜色守恒**（下落不改变各色数量） |
| 死局检测与自动打乱 | 人造死局能被识别并打乱，打乱后必定有解、且不产生现成三连 |
| 关卡目标与星级 | 目标/步数公式、`max(18,…)` 下限、三档星级边界、达标与失败判定 |
| **完整连锁结算（长跑 300 局）** | 300 局随机对局走完全部步数：棋盘不变量、分数单调、道具不越界、死局必被打乱、分数与逐步累加一致 |

长跑一局的实测输出：

```
完整连锁结算（长跑 300 局）   OK   3207 步有效交换，消除 16010 个宝石，最长连锁 7 层，单局最高 4720 分
```

> 写测试当场抓到的 bug：`clear()` 里我先把结果算进了 `outcome`，函数最后却
> `return new ClearOutcome(...)` 又新建了一个——生成道具的信息全丢了
> （`spawnCount` 恒为 0，`SPECIAL_BONUS` 那部分分也没加上）。这种错不改的话，
> 游戏"看起来还能玩"，只是永远不出道具、分数偏低，光靠手动试很难发现。
> 另外"死局检测"那组一开始我自己造错了棋盘：用 `(x+y)%2` 两色铺出来的盘
> **有 84 步可走**，根本不是死局，得用三色 `(x+y)%3` 才是。
